# References, Research & Ecosystem Attribution

`ED:SitAware` builds upon the open data infrastructure, community discussions, and developer tooling created by the *Elite Dangerous* third-party developer community. This document tracks the primary sources, pain-point research, and technical specifications behind the project.

> Links last checked on 27 November 2026. Version-sensitive sources (Journal manual, EDDN schemas) are pinned where noted.

---

## 1. Core Data Infrastructure & APIs
* **EDDN (Elite Dangerous Data Network):** The real-time ZeroMQ firehose (`tcp://eddn.edcd.io:9500`) and upload gateway (`https://eddn.edcd.io:4430/upload/`) that powers live market, outfitting, shipyard, and system state updates across the community.
  * Repository & Schemas: [EDCD/EDDN on GitHub](https://github.com/EDCD/EDDN)
  * Sender rules (authoritative — always the `live` branch): [EDDN Developer Documentation](https://github.com/EDCD/EDDN/blob/live/docs/Developers.md)
* **Spansh:** Public nightly galaxy and station JSON dumps (`galaxy_populated.json.gz`), used to seed 3D star coordinates (`x, y, z`), ring reserves, and station services.
  * Website: [spansh.co.uk](https://www.spansh.co.uk/) · Data dumps: [spansh.co.uk/dumps](https://www.spansh.co.uk/dumps) (served from `downloads.spansh.co.uk`) · API schemas: [docs.spansh.co.uk](https://docs.spansh.co.uk/)
* **EDSM (Elite Dangerous Star Map):** API endpoints for system coordinates, traffic/activity metrics, and optional Commander location fallback.
  * API Documentation: [edsm.net/en/api](https://www.edsm.net/en/api) · Nightly dumps: [edsm.net/en/nightly-dumps](https://www.edsm.net/en/nightly-dumps)
* **Frontier Developments Journal Documentation:** Official schema reference for local `Journal.*.log`, `Market.json`, `Outfitting.json`, and `Shipyard.json` files generated by the game client.
  * Reference: [Elite Dangerous Player Journal Manual v38](https://hosting.zaonce.net/community/journal/v38/Journal_Manual_v38.pdf) (current version — covers Odyssey up to update 26, May 2026)

## 2. Ecosystem Inspiration & Benchmarking
These tools define the current *Elite Dangerous* third-party landscape and inspired the design choices in `ED:SitAware`:
* **Inara ([inara.cz](https://inara.cz/)):** The gold standard for comprehensive galaxy databases, engineer tracking, and "Nearest" searches. *Inspiration:* Highlighted the opportunity for a zero-click, ambient sector briefing rather than manual multi-tab searches.
* **Spansh ([spansh.co.uk](https://www.spansh.co.uk/)):** Unmatched spatial query engine and route plotter. *Inspiration:* Demonstrated the efficiency of 3D bounding-box + Euclidean distance queries over star coordinates.
* **ICARUS Terminal ([iaincollins/icarus](https://github.com/iaincollins/icarus)):** Open-source, diegetic second-screen web interface for Elite Dangerous. *Inspiration:* Showed how clean, cockpit-styled web dashboards enhance immersion on secondary monitors and tablets.
* **EDMC — Elite Dangerous Market Connector ([EDCD/EDMarketConnector](https://github.com/EDCD/EDMarketConnector)) & EDDiscovery ([EDDiscovery/EDDiscovery](https://github.com/EDDiscovery/EDDiscovery)):** The backbone desktop utilities for reading local journals and feeding EDDN. *Inspiration:* Informed our decision to make `ED:SitAware` a two-way citizen that contributes clean market/system snapshots back to EDDN.
* **EDCoPilot ([edcopilot.com](https://www.edcopilot.com)):** Proactive voice/UI companion for nearby points of interest and alerts. *Inspiration:* Validated the value of automated "gotcha" warnings (high-G planets, distant secondary stars, and system hazards) delivered silently via visual badges.

## 3. Community Pain-Point Research & Video References
Design decisions for MVP and Post-MVP features were shaped by recurring Commander discussions across `r/EliteDangerous`, `r/EliteDangerousDevs`, and the Frontier Forums:
* **System Colonisation & Hauling Logistics:**
  * *Video Reference:* [Elite Dangerous System Colonization | The Tools That Change Everything](https://www.youtube.com/watch?v=8SaLRkavF14) (Ricardos Gaming) — Breaks down the logistical friction of sourcing bulk commodities for construction depots and why real-time supply accuracy matters.
* **Stale Market Data & "Phantom" Stations:**
  * Recurring community feedback regarding outdated commodity prices, departed Fleet Carriers, and incomplete colonisation ports led to our **Data Age Badges** (`<2h`, `<24h`, `>24h`) and default **Exclude Fleet Carriers** toggle.
* **Ship-Aware Filtering Friction:**
  * Community requests to stop surfacing Medium-only outposts when flying Large ships (such as the Imperial Cutter, Type-9, or Type-7) drove automatic pad-size detection directly from the player's `Loadout` journal event.
* **Powerplay 2.0 Complexity & Onboarding (Post-MVP Roadmap):**
  * Discussions around the steep learning curve of Powerplay 2.0 control tiers, BGS interactions, and colonisation synergy inspired our planned **Strategic Roadmap & Simplified Waypoint** module.

## 4. Web, Desktop & Community Standards
* **File System Access API:** Used to read local `Journal.*.log` files directly in Chromium-based browsers (Chrome, Edge) without requiring server uploads of private logs. It is not implemented by Firefox or Safari — one reason the desktop wrapper exists. Reference: [MDN — File System API](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API)
* **Tauri v2:** Lightweight Rust-based desktop wrapper used to package the web frontend into a native `.exe` / Linux binary with persistent background file watching. Reference: [v2.tauri.org](https://v2.tauri.app/)
* **r/EliteDangerous Rule 11 — "3rd Party Apps Promoted on this Subreddit Must Have Publicly Visible Source Code":** So the community can inspect promoted apps for safety, including AI-generated code. One reason this project is open source from day one. [Rule announcement](https://www.reddit.com/r/EliteDangerous/comments/1r2c0m2/)
* **EDDN privacy & data-integrity rules:** Send only whitelisted journal events, apply every mandated elision (no Commander-specific data, no `_Localised` keys), and send a sensible `uploaderID`, which the relay obfuscates. References: [EDDN Developer Documentation](https://github.com/EDCD/EDDN/blob/live/docs/Developers.md) · [Journal schema notes](https://github.com/EDCD/EDDN/blob/live/schemas/journal-README.md)
